# Who builds, who reviews, and what the checks need

Recorded 11 November 2026 from Reddi Workbench (`planning/repo-facts.json`, rendered by
`scripts/repo_facts.py`). Change the facts there and render again; do not edit this file.
This repository's own instructions win where they differ. The rules behind this page are
[delivery practices](DELIVERY-PRACTICES.md) 8 to 10.

## Roles

- **Builds:** A coding agent session in a clone.
- **Reviews:** The builder reviews its own work. An independent review happens when the owner asks.
- **Merges:** On the owner's instruction. The repository is public: nothing from a home directory goes in.

## The check command

```sh
scripts/check.sh
```

Hosted CI: No. Paste the check command's output in the pull request before merge. Reddi Workbench's fleet-contract job reads the kit at a pinned commit after the fact.

## What each check needs

"Cloud session" means a cloud agent session with no machine linked to it. A check that
cannot run there is a stop for that session, not a pass: say so in the pull request and
name the machine that has to run it.

| Check | Command | Needs | Runs in a cloud session |
|---|---|---|---|
| Settings and dispatch files, then the sync round trip against throwaway directories | `scripts/check.sh` | bash, jq (real jq, not jaq); omp for the round trip | partly: the static part runs; the round trip is reported NOT RUN (exit 3) without omp |
| Secret scan | `mise exec gitleaks@latest -- gitleaks git --redact .` | mise, network | not tried |
| Model identifiers exist; routing works | `omp models --json; omp config get modelRoles` | a machine with omp and the user's provider logins | no |
