## Ownership and evidence

- Workbench owns this operating practice. ReddiDotAgents distributes a versioned adapter; edit approved sources, never installed managed copies. Preserve user-owned text and project-specific constraints.
- Use the project forge as its durable cross-machine work record and its existing graph for canonical plan IDs. Keep one accountable execution owner per item, stable IDs and private operational evidence; do not create a second editable backlog.
- Before building, test whether acceptance is already met on the default branch and check open pull requests. Prefer valuable Ready outcomes, not make-work per repository. Draft scenarios are not human acceptance.
- Record the common work contract and the evidence profile for code, research, operations, content, design or memory. Run the relevant check, read its actual result, then report; a green check proves only what it exercises.
- Preserve source/base revisions, isolated worktrees, decisions, request IDs, adverse evidence, custody and a concrete next action. Notification, task execution, transport acceptance and peer consumption are distinct states.

## Native execution and Firstmate transition

- Use the current host native task/delegation facilities where permitted. Firstmate is optional continuity infrastructure, not a prerequisite for new work; do not bypass an installed guard or install unmerged Workbench runtime code.
- Drain existing Firstmate work owner by owner at supported safe checkpoints. A handoff identifies the exact heads, approvals, budgets, custody and replacement owner before any legacy writer is retired. No forced reset, process kill, scheduler change, uninstall or deletion follows from policy adoption.
- Host support progresses through planned, installed and exercised evidence. Linux OMP is first; Claude/Codex, then the existing Mac/OpenClaw owner, then other opted-in hosts. An instruction pointer or model catalogue entry is not runtime qualification.

## Capacity and model selection

- Allow no more than five concurrently active spawned agents per model-provider family across projects. Count Claude together, OpenAI together, Gemini/Antigravity together, and Cursor as its own family. Unknown admission evidence means pause or block; do not infer free slots from process liveness.
- Before delegation classify work type, complexity, uncertainty and risk. Everyday or unclear work uses high-tier roles at medium effort; a clear scoped fix uses mid; side jobs use cheap; frontier is reserved for big ambiguous multi-hour work, planned at medium and run at high.
- Resolve approved model role aliases from the adapter once; do not duplicate concrete model names in every project. Quota selects only among authorized lanes. Missing/exhausted/unknown permission pauses work, never authorizes a new provider, local fallback or API entitlement.
- Keep stalled workers genuinely idle at supported checkpoints. Preserve their work and reassess capacity before resume; do not change tiers or restart validation merely to get around a wait.

## Review and protected actions

- The builder reviews its own work as a build step: whole diff re-read, relevant checks and negative cases run, each claim checked against a result. An independent review happens when the owner asks. Never call self-review independent; retain explicitly commissioned security retests.
- Reviews and required checks bind to the unchanged exact head. Fix critical/high findings in the current scope; preserve lower-severity findings as linked follow-ups. Merge only with owner instruction or project standing merge authority.
- Planning, a packet, an advisory hook or a profile is not permission to change live settings, credentials, account access, production infrastructure, spend, publish, deploy, delete or transfer custody. Denied, failed, timed-out or unbounded controls are stops, not bypass opportunities.
- Conserve hosted CI: validate locally, then obtain final-head CI where contracted. Without hosted CI use the named complete local check. A failed or not-run required check is not a pass. Keep the documented docs-only single-rerun exception narrow; never blindly retry a stalled check.

## Consistency and learning

- Pin approved source/adapter hashes and report drift at session start, handoff and tranche boundaries. Do not auto-apply upstream changes or add another daemon/timer. A read-only receipt proves compared artifacts, not model obedience or a hard security/capacity controller.
- Keep optimizer/mod changes outside the baseline. Pilot one supported mechanism at a time with outcome quality, retries, rework, elapsed time and cost when available. Preserve verification tools; make a scoped KEEP/REVERT/HOLD decision without inventing savings.
- At tranche end capture scoped retrospective lessons with provenance and privacy. Agent-authored memory stays proposed until the applicable approval path; never copy private transcripts or auth state into shared knowledge.
